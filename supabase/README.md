# Демонстрационная база

Текущая схема использует числовые `id` в таблицах приложения. Главные таблицы:

| Таблица | Назначение |
| --- | --- |
| `users` | Логин, почта, пароль и данные профиля |
| `posts` | Карточки рецептов в ленте |
| `categories` | Категории рецептов |
| `comments` | Комментарии к карточкам |
| `reactions` | Реакции пользователей |
| `recipes` | Текстовые рецепты профиля и архив; `show_publicly` управляет показом в общей ленте |

Приложение не использует Supabase Auth. Вход и изменения данных выполняет Edge Function `demo-api`. Публичный ключ может читать только ленту, категории, комментарии и реакции. Поле `users.password` доступно администратору в базе, но не выдаётся приложению при загрузке профиля. Данные входа не сохраняются на телефоне. Пока приложение открыто, пароль находится только в памяти и используется для изменений профиля и публикаций; при новом запуске нужно войти снова.

`demo_users_and_sessions.sql`, `archive_visibility_on_users.sql`, `remove_sessions.sql` и `publish_profile_recipes.sql` — история перехода к этой схеме. Остальные SQL-файлы в каталоге описывают старые этапы разработки и не должны применяться поверх текущей базы повторно.

Видимость архива хранится прямо в `users.archive_public`.

Новый текстовый рецепт сразу виден в ленте. В меню архивной записи можно скрыть его из ленты и опубликовать снова; отдельный `posts` для него не создаётся. Рецепты, существовавшие до этого изменения, остались скрытыми до индивидуальной публикации.
